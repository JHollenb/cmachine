# A model you can run, inspect, rewind and replace

cmachine makes a model's computations and live state explicit. These demos show the intended workflow: run an ordinary conversation, branch its state, replace a computation through a declared interface, and check what the next computation actually receives.

**[Interactive showcase](showcase.html)** — clone, then open `demos/showcase.html` locally; GitHub displays its source. · [Supported models and logit error](../docs/SUPPORTED-MODELS.md) · [Capability reference](../docs/CAPABILITIES.md) · [Architecture](../docs/ARCHITECTURE.md)

## Start here: one command, no weights

From a fresh clone, with Python 3, `make` and a C11 compiler:

```sh
python3 demos/run.py tour
```

This verifies eight pinned historical evidence files and the fresh pretrained result bundle, executes the canonical C state/memory/operand fixtures under address and undefined-behavior sanitizers, and runs a small nonlinear state organism. Results go to `demos/output/`. It does **not** load a pretrained model. The pretrained results are checked against their recorded sources; they are not regenerated by this command.

Open `demos/showcase.html` in a browser for the visual tour. It is self-contained and works offline. Rebuild it after changing the tracked results with `python3 demos/render.py`.

The separate [PAN and instruction-Mamba intake panel](../research/model_intake/README.md) exercises the shared C graph executor with generated source maps and symbol tables. PAN matches all 12,769 native predictions with maximum absolute logit error `9.15527e-5`; MambaSan matches 18 generated tokens across two Japanese prompts with maximum error `1.43051e-5` and exact C suffix replay. Their [receipts](../research/model_intake/evidence/README.md) are retained separately from the Qwen demo bundle and are not regenerated by this tour. Their weak task answers remain visible in the model reference.

The organizing question is simple: **can the state we just produced form every operand the next computation needs?** If $x^+=T(x)$ and $z=\Phi(x)$, a closed replacement needs both $\Phi(T(x))=F(z)$ and every future read $R(x)=r(z)$ over its declared scope. The nonlinear demo makes this condition visible. The lexical demo implements a small exact read program. The chat demo supplies the reversible state owner in which more such programs can be tested.

## What the recorded results show

The native Qwen2.5-1.5B-Instruct executor produced this answer to a request for two sentences about bread:

> When yeast is added to dough, it consumes the sugars present, producing carbon dioxide gas. This gas creates bubbles in the dough, causing it to rise.

C owns the token selection, attention/MLP arithmetic and continuing state. Python supplies tokenizer-side text handling. The [integration proof](../docs/evidence/integration-7a6824d/README.md) compares **84 native/reference protocol entries exactly**, including rollback and continuation behavior.

The [recorded operand study](../docs/evidence/context-query-20261106/README.md) reports **16 exact full-logit readouts** using a 15-ID lexical program. Its compilation cost was 47,185,920 linear MACs; its host table occupied 122,940 bytes and transferred 131,072 bytes during candidate execution. Those are source-covered results. Discovery, compilation, transfer and remaining dense computation are paid.

A separate own-history query update reduced mean conditional KL from **0.027105 to 0.023422**, a **13.59%** improvement across four recorded cases. Extending the approximation to a later layer damaged a binding answer despite high retained energy. The showcase includes those answers: this is a local improvement with a visible countertrend.

The bounded memory policy cut tracked session allocation from **48,781,316 to 9,279,620 bytes**, an **80.98% state reduction versus full-byte retention at logical capacity 768**. It also missed all four delayed questions; the full-byte profile answered three of four correctly and missed the sum. Whole-model storage fell much less because learned parameters remained. The runtime makes that tradeoff measurable and reversible; it has not solved sufficient conversational memory.

## Use the runtime as an experiment

The useful unit is a live session with an explicit parent, an explicit operation and an accountable continuation:

```text
A <chat-template token IDs>     consume a supplied user turn
G 16                          let C select and deliver tokens
P                             retain this parent; record returned handle
A <new user-turn suffix>       advance one branch
G 16
B <handle>                    restore the parent
P                             retain a new branch marker
A <alternative suffix>        advance an alternative branch
G 16
K <new handle>                commit the selected branch
```

The [chat client](chat_branch/chat_branch.py) demonstrates the complete protocol, including pending-token ownership, tokenizer view restoration and regenerated replay. The [operand driver](compiled_operands/driver.c) demonstrates the public C APIs for a model-qualified program, persistence, binding, candidate-owned continuation and refusal before mutation. They link to the canonical runtime rather than reimplementing model equations.

Real-model reproduction needs a compatible Qwen bundle and tokenizer, NVIDIA CUDA/cuBLAS and the measured `sm_89` build profile. Weights are not distributed. Follow the per-demo instructions and the [export procedure](../README.md#export-and-chat). The compiled example's result directory must be new.

Within the domains workspace, use mrun for real-model execution. The finite launcher stages exact sources, requests CUDA admission and runs the two model processes sequentially:

```sh
common exec python cmachine/demos/fleet.py stage \
  --model-path /host/path/to/qwen.tcm \
  --tokenizer-path /host/path/to/tokenizer
common exec python cmachine/demos/fleet.py submit /path/printed/by/stage
common exec python cmachine/demos/fleet.py collect JOB_ID
python3 cmachine/demos/verify.py cmachine/demos/fleet-runs/JOB_ID
```

Here `common` denotes the workspace's shared launcher; from `domains/`, its file is `common/bin/common`. The fleet route is pinned to Beast because the model bundle, tokenizer and CUDA architecture are host-local. Collection retains raw evidence; verification runs without a model. The Saturn receipt covers the whole invocation boundary; internal state assertions come from the C driver and native protocol journal.

These examples establish explicit execution, finite exact replay and a limited exact replacement. Cheap general operand formation and forward-pass-free free-form chat remain research goals. [The capability guide](../docs/CAPABILITIES.md) describes what each model and operation currently supports.
