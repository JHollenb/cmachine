# Integration review

The existing user-requested Astra advisor reviewed the canonical merge and commit-verification harness before the fleet run. It confirmed that native mode bypasses the weight registry/tile path, the original reference can use its original header ABI with the shared reporting-only server view, and the twelve model processes are sequential within the previously measured resource envelope.

It identified two blockers before commitment: CUDA extensions had been placed before the primitives they call, and retrying a layer could copy the current row into the reservoir instead of the evicted row. The includes were moved to the translation unit's end. Reservoir copies now read the immutable pre-token snapshot, so a retry is idempotent. The old comment claiming that a refusal cannot touch retained history was corrected.

The model-free fixture checks repeated selected-cache execution byte for byte. The real GPU fixture additionally forces a layer17 read-guard refusal after an occupied reservoir replacement, retries the ordinary layer and requires the same complete arena, addresses and logits as an ordinary child. Existing native writer/gate/parent-lineage tests remain part of both local and pretrained lifecycle checks. Historical frozen experiment sources were preserved unchanged; the correction belongs to the integrated runtime.

The source commit and fresh fleet evidence are recorded separately after the model-free lane. Runtime mechanics, native fidelity, preserved bounded-memory failures and resource accounting remain distinct claims.
